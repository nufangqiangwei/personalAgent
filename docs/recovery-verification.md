# Phase 8 停止、恢复与分支验证

日期：2026-10-20（Asia/Shanghai）。结论：**部分实现，阶段未完成**。T086、T087 保持未勾选，需求评审清单未修改。用户已授权在自定义清单未全部评审时继续实施；这不替代运行时或发布门禁。

## 本轮修复

- 前端事件游标独立于快照游标，重复帧按 `(run_id, sequence)` 去重；补读循环消费全部分页，快照刷新不会跳过尚未接收的事件。
- `stream.reset` 关闭旧连接、清空旧帧、重取快照并重新订阅；丢弃旧连接的迟到帧。重连补读历史，连接错误有界面反馈；已提交事件触发状态、步骤、文档与允许动作刷新。
- 后端历史分页在 `limit=1000` 时额外查询一条，不再丢失第 1001 条对应的下一页游标；游标已清理时，历史接口返回 `EVENT_CURSOR_EXPIRED`，SSE 发送 reset。流读取期间重新检查序号边界。
- 无输入变更的节点重跑可以建立提案；新分支实际从 `fork_step_id` 开始。只读取本分支明确标记复用的前置步骤输出，并恢复文档需要的来源和证据；不再把全部祖先成功输出一起带入。
- 派生草稿建立独立澄清账本并生成可读摘要。分支要求页提交 `BRANCH` 确认，随后返回保留的提案；分支面板不再隐式代替用户确认要求，也不再访问不存在的 `/api/v1/policies`。
- 用户重新选择起点后，影响校验使用新选值；提案、父执行和返回路径保留在路由中。优先顺序和输出约定纳入要求差异，无法映射到流程声明的输入差异保守阻止执行。
- 纠正原有 E2E 中“成功执行仍可取消”的错误预期。测试只检查真实服务返回的允许动作。

## T087 失败门禁

新增 `code/backend/tests/integration/test_phase8_budget_gate.py`。先以正常 Registry 保存更严格的工作流版本，再通过公开 draft/message/confirm/run 接口启动；固定时钟只由注入的外部响应耗时推进，不直接改运行状态或账本。两个参数均在真实引擎执行后断言失败：

- `max_model_requests=1`：预期 `WAITING_USER/BUDGET_LIMIT` 且有 OPEN 求助，实际 `SUCCEEDED`、求助列表为空。
- `max_active_seconds=1`：每次外部响应推进固定时钟 2 秒，预期停止新增动作并求助，实际同样 `SUCCEEDED`、无求助。

失败用例保留在默认测试中，未 skip、未 xfail，不能把检查输出报告为全绿。根因涉及 T105/T106：协调器未把定义中更严格的预算合并到根账本，引擎未落实有效研究时间累计与到限求助。这些缺口已在 Phase 11 列出，本轮没有将局部事件和分支修复冒充预算修复。

依据 `.agents/skills/speckit-implement/SKILL.md` 的 “Halt execution if any non-parallel task fails”，在此失败检查点停止后续阶段实现。需要修复预算、有效时间和求助闭环，再通过本用例及 SC-016 七例/SC-017 六例完整验收。T086 尚缺上述两类 UI 场景，T087 尚未通过，二者均不勾选。
